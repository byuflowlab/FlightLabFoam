# Notes

## Session — 2026-10-22

- Built the first working version from an empty repo: the geometry library, the Flask app, the seven-tab browser UI, and the tests (61 passing). The README's "GUI Design" notes became user and developer docs.
- **Stack.** Flask with plain HTML/CSS/JS and no build step. Launched with `uv run flightlabfoam`. The browser holds the design and sends it whole with each request, and the server's only state is `settings.yaml`. Panel was rejected because its plots are static images and the cutting animation would be clunky.
- **Airfoils are owned here**, not imported from flightlab, to avoid pulling in NeuralFoil and Panel. The 8 `.dat` files are the same ones flightlab bundles, and name lookup follows the same order (embedded, then bundled, then NACA 4-digit), so `.flightlab.json` airfoil names resolve identically.
- **Root/tip matching.** Both ends are sampled at shared cosine chord stations. Feature boundaries are added as warped knots, so a fixed-mm slot lands exactly at both ends even though the chords differ. Projection to the carriages is per point along each wire line, which keeps mixed airfoils and twist exact. Kerf is a mitred outline offset. Feature cuts are kerf-compensated analytically (slots narrower, holes smaller, slits unchanged).
- **Machine frame.** X = 0 is the block's entry face and Y = 0 the block bottom. The entry edge faces X = 0, so trailing edge first turns the airfoil around. Which carriage has the root is derived from the wing half, the entry edge and the `xy_carriage_side` setting (`toolpath.root_carriage`).
- **Feed model.** The first default was `xyz`, which made a straight wing's vertical moves F≈170 because Mach3 counts the other carriage's Z axis. The known-good course output uses a constant F120, so `xy` (F = X/Y carriage speed) is the default, and `xyz`/`all` are options. The 50 mm speed test will settle it.
- uv was not installed on the dev machine. A private copy in the session scratchpad created `pyproject.toml`/`uv.lock` (`uv add`). The user needs `brew install uv` to run it.
- Verified in headless Chrome (Playwright driving the installed Chrome): every tab, panel switching, feature editing, the animation, generate/zip, flightlab import, the settings dialog, and inch display. No console errors. Node on this machine is broken (missing llhttp dylib), so JS was not linted.

## Session — 2026-10-23

- **Point spacing at the leading edge.** Stations changed from full cosine, which also packed points at the trailing edge (0.08 mm gaps there), to a warped half-cosine, x = 1 − cos(π/2·t^p). Default p = 1.25 ("medium"); 1 and 1.5 are "light" and "strong". At 80 points on a 200 mm NACA 2412, the nose gap went from 0.72 to 0.18 mm, and the first 5% of chord went from 11 to 21 points. Aft gaps reach about 5 mm, which is fine on the nearly straight aft surface. p above 1.5 gives gaps below machine resolution.
- **Interpolation.** Station density alone didn't help, because surfaces were linearly interpolated: `naca2412.dat` has no points between x/c = 0 and 0.0125, so the nose was a sharp corner. Each surface is now an Akima spline in u = √(x/c), translated from FLOWMath.jl's `Akima` with delta_x = 0. It matches a line-by-line transcription to 1e-14. On `naca2412.dat` the nose error against the analytic section dropped from 0.47% to 0.15% chord; the 0.15% is the file's own data error and is the same across the whole chord. A not-a-knot cubic spline was tried first and replaced by Akima at Adam's suggestion, since Akima is local and doesn't overshoot. `fx62k131`'s small negative thickness at 99.6% chord is in its data: the surfaces cross there.
- **Controls moved.** Points per surface and leading-edge clustering are now on the Wing design tab, with a spacing readout from `PanelEnds.spacing()`; points are no longer in Cutting settings. Both are still stored in `design.cut`, and older files take the defaults.
- Not done: NACA 4-digit names still resolve to the bundled file first, as in FlightLab, rather than the exact analytic section.
- **Feature entry.** Spars, lightening holes and control-surface cuts now default to entering from the bottom of the wing (`surface = "lower"`); the From / Slit from / Cut from selectors are kept so top entry is still available. Number inputs on that tab step by 0.05.
- **Exit button** in the top bar. It POSTs `/api/shutdown`, which calls an `app.config["SHUTDOWN"]` hook that `__main__` installs (`os._exit` after 0.5 s, so the response reaches the browser). Outside the launcher (tests, `flask run`) there is no hook and the route returns 400. The page replaces itself with a "stopped" message; the design is already autosaved in localStorage.
- **Feature fit checks** (`checks.feature_checks`). `geometry.panel_ends` now records each feature's nominal outline at both ends (`PanelEnds.shapes`, section frame, no kerf), plus the skins (`PanelEnds.skins`). Warnings for: a slot or hole breaking through a skin (judged on the whole outline, not just the centre line); less foam than `machine.min_wall_thickness` (new setting, 2 mm) between a feature and a skin or between two features; and features intersecting. Intersecting is allowed but flagged. Hinge cuts are skipped against the skins, since they go through on purpose. The airfoil's own thickness isn't checked, because every airfoil thins to zero at the nose and tail; the trailing edge has its own minimum. These replaced the two old centre-line-only warnings.
- **Overlapping features can be cut.** A hole, round spar or hinge cut whose entry falls inside a square or U slot on the same surface (at both ends) becomes a child of the slot and is cut from the slot floor. On a U floor the arc is split at each child with a fixed number of points per piece, so root and tip still match. Two overlapping slots, an entry on a slot wall, or two entries at the same place are still errors, because they can't be built as one wire path.

## Session — 2026-10-27

- **Placement tab** (was "Block placement"; still `data-tab="block"`, so the remembered tab still works). It now has three boxes: block size, **Block placement** (where the block sits in the cutting area) and **Panel placement** (cut-in plus the vertical and span-wise offsets of the panel in the block).
- **Block position from program zero.** New `Block.machine_x`/`machine_y`, both 0 by default, which keeps the old convention (program zero is the bottom edge of the entry face) and gives byte-for-byte the same G-code. When they are set, the path starts at program zero, rises to the entry height, moves across to the entry face, then leads in; it leaves the same way, at the exit speed. `Placement.to_block` gives block-frame coordinates (used for the fit checks); `to_machine` adds the offsets. A negative `machine_x` is an error (the wire would start inside the foam). The travel messages now say "program zero" instead of "entry face" or "block bottom".
- **Measuring carriage separation**: measure between the last fixed points where the wire touches each carriage, not between the threaded rods. The software treats the wire as a straight line between those points.
- **Browser checks now use Firefox.** Google Chrome is gone from this machine, so the Playwright scripts stopped working. Selenium in a scratchpad venv now drives the installed Firefox headless. selenium-manager downloaded geckodriver to `~/.cache/selenium`. Firefox needs `-headless -no-remote -new-instance`; without them, a launch while Adam's Firefox is open hands off to it and exits with status 0. Firefox's WebDriver can't see the page's top-level `const` variables (`state`, `anim`), so the scripts use the real inputs. Every tab passed, with no script errors.
- **ResizeObserver loop notice fixed.** The views and the animation canvas redrew synchronously inside their ResizeObserver callbacks. A redraw can toggle the page scrollbar, which resizes the view again, and Firefox reported "ResizeObserver loop completed with undelivered notifications". Redraws now wait for `requestAnimationFrame`, and the canvas sets its height only when it changes.
- **Offset dimensions in the views.** Each nonzero block offset gets a dotted zero line and a dimension line (`dimension()` in views.js) labelled in display units. Top view: X from program zero to the entry face, and the block centre's offset from the midpoint between the carriages. Side view: X from program zero to the entry face (above the block), and Y from program zero to the block bottom (right of the block). Nothing extra is drawn when an offset is 0. The top view's carriage labels moved to the bottom, out from under the legend.
